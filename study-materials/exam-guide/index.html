Cbreak·continue를 표시하고 누적과 덮어쓰기를 구분하기첫 계산 전에 초기값, 실행 경로, 대입 방식 세 가지를 표시한다. 반복 횟수를 다 적지 않아도 값이 변하지 않는 이유와 마지막으로 저장되는 값을 찾을 수 있다.+

2020-1 C switch와 2022-2 Java switch에는 같은 fall-through 사고 과정이 필요하다. 언어가 바뀌어도 콜론 형태의 case에서 break가 없다면 아래로 흐른다. 반복문은 조건→본문→증가 순서를 먼저 그려야 한다. 누적식은 이전 상태를 보존하지만 단순 대입은 지운다. 2020-3의 0 곱셈과 2022-3의 마지막 공배수 문제는 이 차이를 알면 계산량이 크게 줄어든다.

이 순서로 풀기

  1. switch의 일치 case를 찾고 그 위의 문장은 지운다. break가 없으면 아래 case와 default도 계속 실행된다.
  2. continue가 걸린 회차는 그 뒤의 문장을 실행하지 않는다. for에서는 증가식을 거친 뒤 다음 조건으로 간다.
  3. acc += i는 이전 값이 필요한 누적이고 last = i는 덮어쓰기다. 두 변수를 같은 방식으로 더하지 않는다.
  4. 초기값 0에 곱하기만 하는 변수는 계속 0이다. 끝까지 모든 곱셈을 계산할 필요가 없다.
  5. 최종 출력은 printf 형식대로 붙인다. 계산 표의 쉼표나 설명 문장을 출력 답안에 섞지 않는다.
C · 학습 예제
#include <stdio.h>
int main(void) {
    int state = 9, acc = 0, last = 0;
    switch (2) {
        case 1: state += 10; break;
        case 2: state = 4;
        case 3: state += 5;
        default: state--;
    }
    for (int i = 1; i <= 6; i++) {
        if (i % 2 != 0) continue;
        acc += i;
        last = i;
    }
    printf("%d\n%d %d\n", state, acc, last);
    return 0;
}

C포인터는 주소, 역참조는 값: %s와 %c를 따로 읽기문자열 문제를 글자 위치 표로 바꾸면 주소 이동과 문자값 연산이 섞이지 않는다. 같은 원리를 정수 배열에도 적용한다.+

인덱스 표 한 장으로 문자열 이동, 배열 누적, 길이 세기 문제를 연결할 수 있다. 포인터 덧셈은 바이트 수를 그대로 더하는 연산이 아니라 가리키는 자료형 기준의 요소 이동이다. q[-1]은 q의 앞 요소를 뜻하며 이 예시에서는 원래 배열 범위 안이어서 유효하다. 문자열 리터럴은 수정하지 않도록 const char *로 썼다. 문자 수치 연산의 X 출력은 이 예시를 실행한 ASCII 계열 환경의 결과다.

이 순서로 풀기

  1. 문자열 뒤에 종료 문자 \0를 붙이고 각 칸에 0부터 인덱스를 쓴다.
  2. p + k는 k칸 뒤 주소다. *(p + k)는 그 칸의 문자값이다.
  3. %s는 전달된 주소부터 \0 앞까지의 문자열을 출력하고 %c는 문자 하나를 출력한다.
  4. *p + k는 문자 코드의 수치 연산이다. p를 이동시키지 않는다.
  5. 정수 포인터 q가 a + 1이면 *q는 a[1], *(q + 1)은 a[2]다. 포인터 한 칸 이동은 해당 자료형 한 요소 이동이다.
C · 학습 예제
#include <stdio.h>
int main(void) {
    const char *p = "WORLD";
    int a[] = {3, 6, 9};
    int *q = a + 1;
    printf("%s|%c|%c\n", p + 2, *(p + 2), *p + 1);
    printf("%d %d %d\n", *q, *(q + 1), q[-1]);
    return 0;
}
text 인덱스: 0 1 2 3 4 5 값: W O R L D \0 p → text[0], p+2 → text[2]
정수 배열 a: [3] [6] [9] q → a[1], q+1 → a[2], q-1 → a[0]

C구조체 포인터는 레코드 번호와 필드를 먼저 정하기(p + 1)->필드를 한꺼번에 암산하지 않는다. 어느 레코드인지 찾은 다음 어느 열인지 찾는다. 포인터 배열은 주소를 한 번 더 벗겨 읽는다.+

구조체 포인터 문제는 복잡한 수학보다 대상을 고르는 문제다. 계산식을 모두 펼치기 전에 레코드 번호를 확정하면 os/db/hab 같은 비슷한 필드도 혼동하지 않는다. 구조체 멤버를 갱신한 다음 다른 식에서 읽을 때는 반드시 갱신값을 쓴다. 2022-2 Q8 원본은 구조체 정의 뒤 세미콜론이 빠져 있어 그대로 컴파일되지 않는다. 이 학습 코드는 완전한 표준 C 선언을 사용해 개념과 원본 복원 오류를 구분한다.

이 순서로 풀기

  1. 구조체 배열을 행=레코드 번호, 열=멤버 이름인 표로 바꾼다.
  2. p = items 뒤 p++이면 p는 items[1]을 가리킨다. 구조체 한 개 크기만큼 이동한다.
  3. p->x는 (*p).x다. (p+1)->y는 다음 레코드의 y다.
  4. 대입한 필드는 표에 즉시 갱신한다. 이후 계산에서는 갱신된 값을 읽는다.
  5. int *refs[]는 정수값 배열이 아닌 정수 주소 배열이다. refs[1]의 주소를 *로 읽고, **refs는 *refs[0]로 풀어 쓴다.
C · 학습 예제
#include <stdio.h>
struct Item { int x; int y; };
int main(void) {
    struct Item items[] = {{2, 5}, {7, 3}, {4, 8}};
    struct Item *p = items;
    p++;
    p->x += (p + 1)->y;
    int *refs[] = {&items[0].x, &items[1].x};
    printf("%d %d %d\n", p->x, p->y, (p - 1)->x);
    printf("%d %d\n", *refs[1], **refs);
    return 0;
}

refs[0] → items[0].x=2 refs[1] → items[1].x=15 *refs → refs[0]에 저장된 주소 **refs → 그 주소의 정수값 2

  3. 일반 인스턴스 메서드가 같은 서명으로 오버라이드되었다면 실제 객체 Child 구현을 실행한다.

Java · 학습 예제
class Parent {
    int x = 2;
    int score() { return x; }
    int score(int k) { return x + k; }
}
class Child extends Parent {
    int x = 9;
    Child() { super.x = 4; }
    @Override int score(int k) { return x + k; }
    int score(String s) { return s.length(); }
}
public class Main {
    public static void main(String[] args) {
        Parent ref = new Child();
        System.out.println(ref.x);
        System.out.println(ref.score());
        System.out.println(ref.score(3));
    }
}

    int count[3][3] = {{0}};
    for (int y = 0; y < 3; y++) {
        for (int x = 0; x < 3; x++) {
            if (field[y][x] == 0) continue;
            for (int dy = -1; dy <= 1; dy++) {
                for (int dx = -1; dx <= 1; dx++) {
                    int j = y + dy, i = x + dx;
                    if (0 <= j && j < 3 && 0 <= i && i < 3)
                        count[j][i]++;
                }
            }
        }
    }
    for (int y = 0; y < 3; y++)
        for (int x = 0; x < 3; x++)

}

C의 함수 static 지역 변수는 함수 호출이 끝나도 값을 보존한다. 하지만 이름을 사용할 수 있는 범위는 그 함수 안이다. Java의 static 필드는 클래스가 공유하는 한 칸이고, 객체별 필드는 객체마다 따로 생긴다. Java 싱글턴 문제에서는 conn1·conn2·conn3라는 이름 세 개를 세 객체로 세면 틀린다. get()이 같은 객체를 돌려주면 세 참조를 한 상자에 연결하고 count 호출 횟수만 누적한다. 증가 연산은 항상 사용된 값과 저장된 다음 값을 따로 기록하면 안전하다.

  2. 함수를 호출할 때 일반 지역 변수는 새로 초기화한다. static 초기값은 첫 호출 때 한 번만 적용한다.
  3. saved += local을 먼저 실행한다. return saved++는 이전 값을 반환한 뒤 저장된 값을 1 증가시킨다.

동명의 필드는 서로 덮어쓰는 한 변수가 아니라 객체 안의 다른 슬롯이다. 메서드 본문에서 단순히 x를 쓰면 그 본문을 선언한 클래스의 필드를 읽는다. 생성자도 주의해야 한다. 부모 생성자에서 인스턴스 메서드를 호출해도 자식이 같은 서명으로 재정의했다면 자식 메서드가 실행된다. 그 시점에는 자식의 필드 초기화와 생성자 본문이 아직 실행되기 전이어서 자식 int 필드는 0일 수 있다. 2025년 1회 11번처럼 생성자·static 누적·재정의가 섞이면 생성 순서 표와 공유 상태 표를 함께 써야 한다.

이 순서로 풀기

  1. 선언 타입 Base와 실제 생성 타입 Child를 옆에 적는다. 객체 안에는 부모 x와 자식 x가 따로 존재한다.
  2. new Child()는 부모 생성자를 먼저 실행하므로 P 뒤에 C를 출력한다.
  3. a.x는 선언 타입 Base의 필드 2를 선택한다. a.value()는 같은 서명이 재정의되어 실제 객체 Child의 메서드를 실행한다.
  4. a.tag()는 static 메서드이므로 선언 타입 Base의 tag를 선택한다. 필드·메서드·static을 한 규칙으로 처리하지 않는다.

배열을 함수 매개변수 int p[]로 받아도 실제 매개변수는 포인터로 조정된다. *p를 바꾸면 원본 배열 첫 원소가 바뀌지만 p라는 지역 포인터 자체를 다른 주소로 바꾸면 호출자 포인터는 바뀌지 않는다. 호출자 포인터까지 변경하려면 int**와 같은 한 단계 더 높은 주소가 필요하다. 문자열 복사에서는 문자를 옮기는 것에 더해 마지막 \0도 기록해야 이전 긴 문자열의 뒷부분이 붙지 않는다. 함수 포인터의 int *(*go)(int *)는 int* 인수를 받아 int*를 반환하는 함수의 주소라는 순서로 읽는다.

이 순서로 풀기

  2. %s는 그 주소부터 \0 직전까지 읽는다. %c는 문자값 하나를 출력한다.
  3. *(p+1)은 주소를 이동한 뒤 읽기, *p+1은 읽은 문자값에 더하기로 분리한다.
  4. 함수 포인터도 호출 결과의 자료형을 추적한다. go(x)는 int*를 돌려주므로 앞의 *가 그 주소의 정수 26을 읽는다.

struct Actions { int *(*go)(int *); };
int main(void) {

    char *p = text + 1;

    int x[] = {10, 26};
    struct Actions actions = {step};
    int value = *actions.go(x);
    printf("%d/%x\n", value, (unsigned int)value);
    return 0;
}

typedef struct Node { int v; struct Node *next; } Node;
int main(void) {
    Node a = {2, NULL}, b = {5, NULL}, c = {8, NULL};
    a.next = &c; c.next = &b;
    Node *head = &a;
    int t = head->v;
    head->v = head->next->v;
    head->next->v = t;
    Node *prev = head->next;
    Node *last = prev->next;
    prev->next = last->next;
    last->next = head;
    head = last;
    for (Node *p = head; p != NULL; p = p->next)
        printf("%d%s", p->v, p->next ? " " : "\n");
    return 0;
}

NULL을 포함한 비교는 보통 UNKNOWN이다. UNKNOWN OR TRUE는 TRUE이고 UNKNOWN OR FALSE는 UNKNOWN이어서 WHERE에서는 탈락한다. 2025년 3회 20번 같은 OR 조건에서는 왼쪽 열이 NULL이라는 이유만으로 즉시 행을 버리면 안 된다. GROUP BY 없는 COUNT 쿼리는 조건에 맞는 행이 0개여도 0을 담은 결과 행 하나를 반환한다. COUNT(DISTINCT dept)가 1이라는 값과 결과가 1행이라는 말은 우연히 같을 수도 있지만 다른 질문이다. 이 자체 예제는 RIGHT JOIN을 지원하는 SQLite 환경에서 검증했다.

이 순서로 풀기

  1. RIGHT OUTER JOIN은 오른쪽 B의 모든 행을 보존한다. B.id=1은 A의 두 행과 일치하므로 두 결과 행이 생긴다.
  2. B.id=3,4는 일치하는 A가 없지만 남고 A 열은 NULL로 채워진다. 조인 결과는 총 4행이다.
  3. COUNT(*)는 4행 전부, COUNT(A.v)는 NULL 아닌 값 10 한 개만 센다.
  4. A.id IS NULL은 불일치 행 두 개를 고른다. = NULL로 비교하면 참이 되지 않는다.

공개키 암호를 모든 상황에서 '공개키로 암호화하고 개인키로 복호화'라고만 외우면 서명·키 합의와 섞인다. 이번 기출의 대칭·비대칭 분류 문제에서는 키가 같은가, 쌍인가를 우선 적용한다. 해시와 암호의 목적을 먼저 나누는 방법은 지문이 짧아도 유효하다.

이 순서로 풀기

  1. 원문을 되돌릴 필요가 없고 고정 길이 값을 만들면 해시 후보를 본다. 암호화는 적절한 키로 평문을 복원하는 절차가 있지만 해시는 복호화 절차가 없다.
  2. 암호화와 복호화에 같은 비밀키를 쓰면 대칭키다. AES·DES·SEED·ARIA·IDEA 등이 여기에 속한다. 공개키와 개인키의 쌍을 활용하면 비대칭키다. RSA·ECC가 대표적인 기출 분류다.
  3. AES는 블록 128비트를 고정하고 키가 128·192·256비트다. AES-256이라는 이름을 보고 블록도 256비트라고 쓰지 않는다.
  4. DES는 블록 64비트, 유효 키 56비트, 16라운드라는 세 수치를 연결한다. IDEA는 64비트 블록·128비트 키, Skipjack은 64비트 블록·80비트 키라는 기출 식별 단서를 따로 기억한다.
  5. 해시에서는 입력 처리 블록과 최종 출력 길이를 구분한다. MD5의 512비트는 입력 처리 블록, 128비트는 결과 길이다. SHA-256의 결과는 256비트다.
  6. 무결성 확인 예: 보낸 파일과 받은 파일의 해시를 각각 계산해 비교한다. 같은 값이라고 원본의 신원까지 자동 보장되는 것은 아니므로 인증된 해시 전달·MAC·전자서명과 구별한다.

자주 틀리는 지점

해시를 '암호화해서 나중에 복호화하는 값'으로 설명하면 틀린다. MD5·DES는 기출 용어를 식별하기 위한 학습 대상으로 다루고 신규 보안 설계의 기본 선택으로 제시하지 않는다.

셀프 체크 · AES-256으로 128비트 한 블록을 처리할 때 키 길이와 블록 길이는 각각 얼마인가? 또 SHA-256 결과를 키로 복호화할 수 있는가?

AES의 키는 256비트, 블록은 128비트다. SHA-256은 해시이므로 결과를 복호화해서 원문을 복원하는 절차가 없다.

비트 AND로도 검산할 수 있다. 연습 예에서 150=10010110, 192=11000000이므로 AND는 10000000=128이다. 블록 계산이 빠른 풀이이고 AND는 확인 도구다. 2026-2 Q14의 .0~.15는 주소 16개=2^4개이므로 호스트 4비트, 프리픽스 32−4=28이다. 원래 /27이라는 표현보다 실제로 분할된 범위를 기준으로 읽는다.

이 순서로 풀기

  1. 마스크의 1비트 수가 프리픽스 길이다. 255.255.255.192는 8+8+8+2=26이므로 /26, 호스트 비트는 32−26=6이다.
  2. 부분 마스크 옥텟에서 블록 크기=256−마스크값을 계산한다. /26의 마지막 옥텟은 256−192=64이므로 시작점은 0·64·128·192다.
  3. 독립 연습 예: 192.168.7.150/26의 150은 128 이상 192 미만이다. 네트워크는 192.168.7.128, 다음 블록 시작 직전인 192.168.7.191이 브로드캐스트다.
  4. 일반적인 IPv4 서브넷에서 사용 가능한 호스트는 시작+1부터 끝−1까지다. 예의 범위는 .129~.190, 개수는 2^6−2=62다. /31 점대점 링크·/32 등은 별도 규칙을 적용한다.
  5. 세 번째 옥텟에서 변하면 네 번째 옥텟도 함께 범위에 넣는다. 192.168.35.10/22의 블록 크기는 256−252=4, 세 번째 옥텟 35는 32~35에 속한다. 네트워크 192.168.32.0, 브로드캐스트 192.168.35.255다.
  6. FLSM으로 최소 3개 서브넷이 필요하면 2^b≥3을 만족하는 최소 b=2비트를 빌린다. /24→/26, 4개 블록 중 3개를 사용한다. 두 번째 블록은 .64~.127이므로 브로드캐스트는 .127이다.

프로토콜의 기본 요소는 구문·의미·타이밍이다. 형식과 구조, 정보와 제어의 뜻, 교환 순서·시점을 구별한다. 오류 코드의 세부 능력은 코드 종류·구성에 따라 달라지므로 '해밍 계열이니 모든 2비트 오류를 교정한다'처럼 확대하지 않는다. 흐름 제어·오류 검출·오류 정정도 서로 다른 역할이다.

이 순서로 풀기

  1. 계층의 동작 단위를 붙인다. 물리 계층은 비트·전기적 연결, 데이터 링크는 인접 노드 간 프레임·MAC·오류 검출, 네트워크는 IP 패킷·경로 선택, 전송은 포트·종단 간 전송을 다룬다.
  2. ARP는 IP→MAC, RARP는 MAC→IP, ICMP는 네트워크 상태·오류 제어 메시지라는 방향을 적는다. ICMP는 데이터 자체의 신뢰성 있는 전송을 보장하는 TCP의 대체물이 아니다.
  3. RIP는 홉 수, OSPF는 링크 비용을 기준으로 본다. RIP는 거리 벡터·Bellman-Ford, OSPF는 링크 상태·Dijkstra라는 쌍을 연결한다.
  4. 독립 그래프 예: A→B→D는 2홉·비용 20, A→C→E→D는 3홉·비용 3이라고 하자. RIP는 2홉 경로를, 주어진 비용을 쓰는 OSPF는 비용 3 경로를 고른다.
  5. 오류제어는 스스로 고치는가 다시 보내 달라는가로 분류한다. FEC는 수신측에서 오류 정정, BEC/ARQ는 오류 검출 후 재전송이다. CRC는 다항식 기반 검출, 패리티는 1의 개수의 홀짝을 검사한다.
  6. HDLC는 데이터 링크의 비트 지향 프로토콜이다. I 프레임은 정보, S 프레임은 감독·흐름/오류 제어, U 프레임은 연결 관리 등의 비번호 기능으로 묶는다.

이론운영체제 계산: 시간축과 최근 사용 목록을 따로 그리기스케줄링은 CPU 실행 순서, 페이지 교체는 메모리 내용의 변화다. 둘 다 매 순간의 상태를 기록해야 하며 최종 답만 머릿속으로 추측하면 틀리기 쉽다.+

이 장의 SRT와 RR 결과는 제공된 실행시간을 직접 계산한 것이다. CPU 유휴 구간이 생기면 시간축에 빈 구간을 반드시 남기고, 프로세스의 실행 구간 길이 합이 최초 버스트 시간과 같은지 확인한다. 페이지 교체도 매 단계에서 프레임 수가 한도를 넘지 않는지, hit+fault가 총 참조 수와 같은지 검산한다.

이 순서로 풀기

  1. 스케줄링 표에 도착·실행·남은 시간·완료를 만든다. 대기시간=완료−도착−실행, 반환시간=완료−도착이다. 선점되면 여러 구간을 실행하므로 최초 시작−도착만으로 대기시간을 구할 수 없다.
  2. SJF는 준비된 작업 중 실행시간이 가장 짧은 작업을 비선점으로 고른다. SRT는 새 작업이 오면 현재 작업의 남은 시간과 비교한다. RR는 시간 할당량만큼 실행한 미완료 작업을 큐 뒤로 돌린다.
  3. 기출 SRT 수치 A(0,8), B(1,4), C(2,9), D(3,5)를 직접 추적하면 0~1 A, 1~5 B, 5~10 D, 10~17 A, 17~26 C다. 도착 2·3 시점에도 B의 남은 시간이 3·2로 가장 짧아 계속 실행한다.

  1. 머리글의 열 수가 Degree/차수, 데이터 행 수가 Cardinality/카디널리티다. 머리글은 튜플 수에 넣지 않는다. 릴레이션 스키마는 구조, 인스턴스는 특정 시점의 실제 데이터다.
  2. 후보키 판정은 두 번 검사한다. 모든 행을 유일하게 식별하는가, 속성 하나를 빼도 여전히 식별되는가. 뺄 수 있으면 최소성이 없으므로 그 집합은 후보키가 아니다.
  3. 독립 예: 학생(학번, 이름, 학과)에서 학번이 업무상 유일하다면 {학번}은 후보키, {학번,이름}은 슈퍼키다. 이름은 현재 표에서 우연히 다르더라도 동명이인을 허용하면 후보키가 아니다.
  4. 여러 후보키 중 선택한 것이 기본키, 선택하지 않은 것이 대체키다. 외래키는 다른 테이블의 참조 대상 키를 가리키는 속성 집합이다. 외래키 자체에 중복이 있어도 된다.
  5. 개체 무결성은 기본키의 NULL·중복 금지, 참조 무결성은 외래키가 유효한 참조값이어야 한다는 조건이다. NULL 허용 여부는 해당 제약과 업무 조건을 따로 확인한다.

'슈퍼키는 최소성을 만족하지 않는다'는 지문을 절대 규칙으로 외우지 않는다. 슈퍼키는 최소성을 요구하지 않으며 최소한의 슈퍼키가 바로 후보키다. 표의 현재 값만 보고 영구적인 키를 단정할 수도 없다.

이론정규화: 제거할 종속 관계를 먼저 표시하기정규형 이름은 표의 모양이 아니라 후보키와 함수적 종속으로 결정한다. 기본키 일부에만 의존하는지, 비키 속성을 거쳐 의존하는지부터 그린다.+

기출의 정규화 문제를 풀 때 '표가 두 개로 나뉘었으니 2NF'라고 결론 내리면 안 된다. 어느 종속을 제거했는지로 판단한다. 3NF의 엄밀한 조건은 비자명 X→A에 대해 X가 슈퍼키이거나 A가 주요 속성인 것이다. BCNF는 뒤의 예외를 허용하지 않으므로 3NF보다 강하다. 이 구분이 3NF·BCNF 선택 문제의 핵심이다. 2026-2 Q11의 조건부 추론에서 강사번호→과정명이 표본에서 모순되지 않는다는 점과 그 업무 제약이 영구 보장된다는 점을 구별한다. 수험 답으로는 전형적인 출제 의도인 3NF를 제시하되, 확정 근거에 추가 가정이 포함된다는 사실을 명시한다.

이 순서로 풀기

  1. 업무 제약에서 후보키와 함수적 종속을 적는다. X→Y는 같은 X를 가진 두 튜플의 Y도 같아야 한다는 뜻이다. 우연히 현재 값이 같은 것과 지속적으로 보장되는 종속은 다르다.
  2. 독립 예: 수강(학번,과목,학생이름,강사번호,강사전화), 후보키 {학번,과목}; 학번→학생이름, 과목→강사번호, 강사번호→강사전화라는 제약을 가정한다.
  3. 1NF는 원자값을 전제로 한다. 2NF로 갈 때 복합 후보키 일부의 종속을 제거한다. 예에서 학생(학번,학생이름), 과목(과목,강사번호,강사전화), 수강(학번,과목)으로 분리하면 키 일부 의존을 없앨 수 있다.
  4. 3NF로 갈 때 과목→강사번호→강사전화의 이행 종속을 분리한다. 강사(강사번호,강사전화)를 만들고 과목에는 과목·강사번호만 남긴다.
  5. BCNF는 모든 비자명 함수적 종속의 결정자가 슈퍼키여야 한다. '결정자가 모두 후보키'는 시험용 약식 표현으로 자주 보이지만 엄밀한 기준은 슈퍼키다. 4NF는 다치 종속, 5NF는 조인 종속을 다룬다.
  6. 비정규화는 성능·운영 목적에 따라 중복·통합 등을 의도적으로 도입하는 작업이다. 정규화처럼 이상을 없애는 목적과 반대로 중복 관리 책임이 커질 수 있으므로 목적·위험을 함께 설명한다.

  2. 독립 송금 예: A계좌에서 10 차감 후 B계좌에 10 추가한다. 차감만 하고 장애가 났다면 부분 결과를 취소해야 원자성을 지킬 수 있다. 완료한 송금이 재시작 후 사라지지 않아야 지속성을 지킨다.
  3. 로그에서 T1의 commit이 있고 DB 반영이 일부 누락될 수 있으면 REDO로 완료 결과를 재반영한다. T2가 commit 전에 변경했다면 UNDO로 이전 값을 복원한다.
  4. 독립 로그 예: T1 start, X:100→90, T1 commit, T2 start, Y:50→70, 장애. 즉시 갱신의 단순 회복 예에서는 T1을 REDO, T2를 UNDO 대상으로 분류한다. 로그에 저장된 새 값·이전 값의 역할을 구분한다.
  5. 즉시 갱신은 완료 전 변경이 DB에 반영될 수 있어 미완료 변경의 UNDO가 필요할 수 있다. 지연 갱신은 commit 전 변경을 DB에 적용하지 않는 기본 방식이므로 미완료 트랜잭션에 대한 DB UNDO를 하지 않는다.
  6. Locking은 데이터 접근을 잠금 규칙에 따라 조절하는 병행제어다. 로그를 보고 복원하는 회복과 잠금으로 동시 접근을 통제하는 병행제어를 같은 작업으로 설명하지 않는다.

  3. Adapter와 Bridge를 비교한다. 이미 맞지 않는 인터페이스를 변환하면 Adapter, 추상과 구현을 분리해서 두 방향으로 독립 확장하면 Bridge다. 둘 다 연결을 다루지만 해결하는 문제가 다르다.
  4. Observer는 상태 변화가 구독자들에게 전달되는 일대다 알림, Iterator는 내부 구조를 노출하지 않고 순차 접근, Visitor는 데이터 구조와 연산을 분리해 연산을 추가하는 방식이다.
  5. Singleton은 특정 범위에서 인스턴스 한 개를 제공하는 생성 패턴이다. '동시 참조가 불가능'이 본질은 아니며 동시성 안전성은 구현 문제다.
  6. Facade는 복잡한 하위 시스템에 간단한 진입점, Proxy는 다른 객체 접근의 대리자, Decorator는 같은 인터페이스를 감싸 기능 추가, Composite는 단일 객체와 집합을 동일하게 취급한다. 혼동되는 구조 패턴은 역할 한 줄로 비교한다.

분모도 중요하다. 커버리지=실행한 대상 수/전체 대상 수×100이다. 문장 수, 분기 결과 수, 개별 조건 결과 수는 서로 다른 분모다. 코드 문제가 포함되면 어떤 줄을 실행했는지뿐 아니라 어느 조건을 실제 평가했는지도 추적한다. 이 장의 진리표는 논리 조합을 설명하기 위한 독립 예이며 언어별 실제 계측 규칙을 숨기지 않는다.

이 순서로 풀기

  1. 독립 예를 D=A||B로 둔다. 문장 커버리지는 모든 실행 문장을 적어도 한 번 실행, 분기/결정 커버리지는 D의 참·거짓, 조건 커버리지는 A와 B 각각의 참·거짓을 대상으로 한다.
  2. 입력 조합 (T,F),(F,T)는 A와 B가 각각 참·거짓이지만 D는 두 번 모두 참이다. 따라서 논리 조건 표상 조건 커버리지는 만족해도 분기 커버리지는 만족하지 않는다.
  3. 입력 조합 (T,T),(F,F)는 D의 참·거짓과 A·B의 참·거짓을 갖지만, 각 조건이 독립적으로 결과를 바꿨다는 증명은 없다. MC/DC는 다른 조건을 유지한 비교쌍을 요구한다.
  4. D=A||B의 MC/DC는 (F,F),(T,F),(F,T)의 세 조합으로 보인다. A 효과: (F,F)↔(T,F), B 효과: (F,F)↔(F,T). 각 쌍에서 다른 조건은 고정되고 D만 바뀐다.
  5. 실제 C·Java 등에서는 단락 평가를 확인한다. A가 참이면 A||B의 B는 실행되지 않을 수 있다. 논리 진리표에서 B 값을 정한 것과 B 조건식이 실제 평가된 것을 구별한다.
  6. 순서도 문제는 분기점마다 참·거짓 간선을 표시하고 경로 집합이 간선을 모두 지나가는지 검산한다. 실행 문장을 모두 지났다고 분기까지 모두 지났다고 결론 내리지 않는다.

권한 문제는 적은 학습량으로 안정적으로 풀 수 있는 계산형이다. 심볼릭 링크 공격에서는 '확인한 파일'과 '실제로 여는 파일'이 같다는 보장이 깨진다는 과정을 설명할 수 있어야 한다. 소유자·그룹·기타 사용자의 기본 권한 예는 특별 권한 비트를 포함하지 않는 3자리 조건을 전제로 한다.

이 순서로 풀기

  1. 각 대상의 권한을 따로 더한다. rwx=4+2+1=7, r-x=4+1=5, --x=1이다. 소유자 rwx·그룹 r-x·기타 --x이면 chmod 751 a.txt다.
  2. 독립 연습으로 chmod 640 memo.txt를 읽으면 소유자 rw-(6), 그룹 r--(4), 기타 ---(0)이다. 숫자를 보고 권한 문자로 역변환해 검산한다.
  3. pwd는 현재 경로, ls는 목록, cd는 경로 이동, cp는 복사, cat은 내용 출력, ps는 프로세스 확인이다. 경로·파일 내용·프로세스라는 출력 대상을 구별한다.
  4. 심볼릭 링크는 대상 경로를 가리키는 별도 링크다. 경로를 가리키는 링크와 같은 파일의 inode를 참조하는 하드 링크를 구별한다. 대상이 사라지면 심볼릭 링크는 깨진 링크가 될 수 있다.
  5. 임시 파일 공격 지문은 확인과 사용 사이에 대상이 바뀌는 경쟁 조건을 본다. 공격자가 링크를 바꿔 권한 높은 프로세스가 다른 파일을 쓰게 만드는 것이 핵심이다. 2026-1 Q14의 빈칸은 링크 종류의 이름을 묻는다.
