예상 변형 (double)(sum/n)과 (double)sum/n을 대비하거나, 문자열 상수의 위치를 덧셈 앞뒤로 이동하는 변형이 가능하다. &&와 ||의 순서·경계 인덱스·시프트 수·나머지 수를 바꾸는 변형도 대비할 수 있다.

#include <stdio.h>
typedef struct Node { int value; struct Node *next; } Node;
int main(void) {
    Node a = {4, NULL}, b = {7, NULL};
    Node c = {1, NULL}, d = {9, NULL};
    a.next = &b; b.next = &c; c.next = &d;
    Node *head = &a;
    Node *moved = head->next->next;
    head->next->next = moved->next;
    moved->next = head;
    head = moved;
    head->next->value += head->value;
    int total = 0;
    for (Node *p = head; p != NULL; p = p->next) {
        total = total * 2 + p->value;
        printf("%d%s", p->value, p->next ? " " : "\n");
    }
    printf("code=%d", total);
    return 0;
}

C · 독립 제작 문제
#include <stdio.h>
int main(void) {
    int stack[4], top = 0;
    stack[top++] = 2;
    stack[top++] = 5;
    int first = stack[--top];
    stack[top++] = first - 1;
    int queue[4], front = 0, rear = 0;
    queue[rear++] = stack[--top];
    queue[rear++] = stack[--top];
    int x = queue[front++];
    queue[rear++] = x + 3;
    printf("%d|", x);
    while (front < rear) {
        int value = queue[front++];
        printf("%d", value);
        if (front < rear) printf(" ");
    }
    return 0;
}

  2. first-1인 4를 push해 스택은 [2,4]다. 다시 pop하면 4, 다음 pop은 2다.

외부 조인 중복과 그룹별 NULL 개수

SQL · 독립 제작 문제
CREATE TABLE Members(id INTEGER, grp TEXT);
CREATE TABLE Scores(mid INTEGER, points INTEGER);
INSERT INTO Members VALUES (1,'A'),(2,'A'),(3,'B'),(4,'B'),(5,'C');
INSERT INTO Scores VALUES (1,70),(1,NULL),(2,90),(5,100),(9,20);
SELECT m.grp,
       COUNT(*) AS rows_all,
       COUNT(s.points) AS scored,
       COALESCE(SUM(s.points),0) AS total
FROM Members AS m LEFT JOIN Scores AS s ON m.id = s.mid
GROUP BY m.grp
HAVING COUNT(*) > COUNT(s.points)
ORDER BY m.grp;

겨냥하는 능력 RIP 경로 선택과 OSPF의 링크 비용을 비교하는 기출 근거의 독립 계산 연습이다. 새로운 그림의 모든 링크를 명시한다.

라우터 A·B·C·D·E·F를 잇는 양방향 링크는 다음 여섯 개뿐이다. A-B 비용7, B-F 비용8, A-C 비용1, C-D 비용1, D-E 비용1, E-F 비용1. 한 링크 통과를 1홉으로 센다. OSPF는 주어진 링크 비용의 합을 사용한다. A에서 F까지 ① RIP가 선택할 경로와 홉 수 ② OSPF가 선택할 경로와 비용 합을 구하시오. 최적 경로 동률은 없다.

정답·독립 풀이 확인

정답

② OSPF: A → C → D → E → F, 비용 4

풀이 순서

  1. 가능한 두 단순 경로를 먼저 적는다. 짧은 연결은 A-B-F, 긴 연결은 A-C-D-E-F다.
  2. RIP 기준은 홉 수. 첫 경로는 링크 2개라 2홉, 두 번째는 링크 4개라 4홉이다.
  3. 따라서 RIP는 A-B-F를 선택한다. 선 위의 7과 8을 홉 수로 더하지 않는다.
  4. OSPF 예의 기준은 링크 비용 합. A-B-F는 7+8=15, A-C-D-E-F는 1+1+1+1=4다.
  5. 따라서 OSPF는 비용4의 A-C-D-E-F를 선택한다. 경로 선택 기준을 먼저 정해야 같은 그림을 두 방식으로 풀 수 있다.

응용 확장: 호스트 70개를 수용하는 최소 크기

겨냥하는 능력 기출의 호스트 수 계산·동일 크기 분할을 역으로 적용한 확장 연습이다. 역산 요구 자체가 업로드 자료에서 별도로 출제됐다고 단정하지 않는다.

192.168.80.0/24 안에서 장치 70개를 모두 수용할 수 있는 가장 작은 일반 IPv4 서브넷 크기를 선택한다. 네트워크·브로드캐스트 주소는 호스트에 할당하지 않는다. ① 최대 가능한 프리픽스 길이 ② 마스크 ③ 서브넷 하나의 사용 가능 호스트 수 ④ 이 크기로 /24를 나눌 때 생기는 서브넷 수 ⑤ 첫 번째 서브넷의 네트워크·브로드캐스트를 구하시오.

정답·독립 풀이 확인

정답

① 25
② 255.255.255.128
③ 126
④ 2
⑤ 192.168.80.0 / 192.168.80.127

풀이 순서

  1. 필요한 호스트 비트 h는 2^h−2≥70을 만족해야 한다. 6비트면 64−2=62라 부족하다.
  2. 7비트면 128−2=126이므로 충분하다. 가장 작은 크기를 원하므로 h=7을 선택한다.
  3. 프리픽스는 32−7=25. 마지막 옥텟 마스크는 10000000=128이다.
  4. 블록 크기=256−128=128주소. /24의 256주소를 128주소씩 나누므로 두 개의 /25 서브넷이 생긴다.
  5. 첫 블록은 .0~.127, 둘째는 .128~.255다. 첫 블록의 네트워크 .0, 브로드캐스트 .127, 호스트 .1~.126으로 검산한다.

함정

70이 64보다 조금 크다고 /26을 선택하지 않는다. 호스트 수는 주소 수에서 양 끝 두 개를 뺀 값이다. 프리픽스가 클수록 네트워크 크기는 작아진다는 방향도 확인한다.

한 줄을 바꾸면?

장치가 60개면 /26의 62개로 충분하다. 63개면 /26은 부족하여 /25가 필요하다. 이 두 값을 비교하면 2주소 제외의 의미가 분명해진다.
